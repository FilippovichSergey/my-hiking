# Мае паходы

Сайт-карта маіх хайкінгаў: трэкі з Komoot, фота, відэа з YouTube і ўражанні.
Беларуская і англійская мовы, светлая і цёмная тэма, 3D-рэльеф, фільтры і агульная статыстыка.
На старонцы паходу можна спампаваць трэк у GPX і скапіяваць спасылку на паход.

## Як дадаць новы паход

1. Запішы тур у Komoot (від спорту «Пешы паход» або «Альпінізм»).
   Шматдзённы паход = асобны тур на кожны дзень.
2. Скапіюй 10–20 лепшых фота ў падтэчку `Сайт` у тэчцы паходу:
   `F:\Фота і відэа\20250517_Зялёнае_возера\Сайт\`.
   Падыходзіць і назва `для сайту`.
3. У тэрмінале ў `D:\IT\my-hiking`:

   ```powershell
   .\hike komoot    # спампаваць туры (спытае email і пароль Komoot)
   .\hike youtube   # абнавіць спіс відэа, калі выйшла новае
   .\hike new       # стварыць чарнавік content\hikes\<дата-назва>.yaml
   ```

4. Адкрый новы `.yaml` і дапішы: англійскую назву, складанасць, уражанні.
   Правер, ці правільна падабраныя відэа.
5. Збяры і паглядзі сайт:

   ```powershell
   .\hike build     # фота → WebP, трэкі, docs\data\hikes.json
   .\hike serve     # http://localhost:8000
   ```

6. Апублікуй:

   ```powershell
   git add -A
   git commit -m "Паход: Зялёнае возера"
   git push
   ```

## Файл паходу (`content/hikes/*.yaml`)

```yaml
date: 2025-05-17
end: 2025-05-18             # толькі для шматдзённага паходу без трэку
title:
  be: "Зялёнае возера"
  en: "Green Lake"          # калі пуста, паказваецца беларуская назва
region:
  be: "Аджарыя"
  en: "Adjara"
difficulty: medium          # easy | medium | hard | expert
photos_folder: "20250517_Зялёнае_возера"
cover: _MG_0945.JPG         # неабавязкова; інакш першае фота па часе здымкі
komoot:                     # туры аднаго дня аб'ядноўваюцца ў адзін дзень
  - 1234567890
youtube:
  - VQ3BMsY4Fjs
location: [41.65, 41.87]    # [шырата, даўгата] толькі для паходу без трэку
hidden: true                # неабавязкова: схаваць паход з сайта
impressions:
  be: |
    Першы абзац.

    Другі абзац (абзацы раздзяляюцца пустым радком).
  en: |
    First paragraph.
```

Даты паходу з трэкам: пачатак — `date`, але не пазней за першы дзень трэку (назва тэчкі магла «з'ехаць» на
дзень), канец — апошні дзень трэку. Без трэку канец задае `end`; няправільны `end` (напрыклад, 31 лютага
ў двукоссі) адкідаецца з папярэджаннем.

`hike build` спыняецца з паведамленнем і не змяняе індэкс сайта, калі ў файле паходу памылка YAML (у тым
ліку неісная дата без двукосся) або ў паходу няма ні сапраўднай `date`, ні трэку з датай.
Тур, паўтораны ў `komoot:`, улічваецца адзін раз.

Калі тур або тэчку не трэба ператвараць у паход, дадай іх у `content/ignore.yaml`.
Туры, даты якіх трапляюць у выключаную тэчку, таксама прапускаюцца.
`hike new` ніколі не перазапісвае існуючыя файлы: пры супадзенні імя дадаецца `-2`, `-3`…

## Практычная частка

На старонцы паходу ёсць блок «Практычная інфармацыя». Пад кожнай яго часткай падпісана, адкуль даныя.

**«Разлік па трэку»** — лічыцца сам пры `hike build`, нічога пісаць не трэба:

* тып маршруту: колавы, туды і назад, з пункта А ў пункт Б, змешаны (для шматдзённага — і для кожнага дня);
* старт і фініш: час, вышыня, спасылка «Маршрут да старту»;
* светлавы дзень (узыход і заход без уліку рэльефу) і запас святла пасля фінішу;
* тэмп: хуткасць у руху і час на прыпынкі; рэльеф: набор на кіламетр, найкруцейшыя 500 м пад'ёму і спуску.

Тып маршруту паказваецца на картцы ў спісе, па ім можна фільтраваць.

**«Мае назіранні»** — блок `practical:` у файле паходу. Усе палі неабавязковыя; пустое поле азначае «няма
звестак», а не «няма» ці нуль. Тэкст можна пісаць радком або на дзвюх мовах: `{be: "...", en: "..."}`.

```yaml
practical:
  checked: 2025-05-17            # калі звесткі правераны (па змаўчанні — дата паходу)
  route_type:                    # толькі каб выправіць разлік: loop | out_and_back | point_to_point | mixed
  weather_notes: "Раніцай туман, на хрыбце моцны вецер."
  water:
    drunk: 2.5                   # выпіта, л (для шматдзённага — спіс па днях: [2.5, 3])
    taken: 3                     # неабавязкова: узята на старце, папоўнена, засталося
    refilled: 1
    left: 1.5
    available: true              # ці ёсць вада на маршруце: true | false
    sources:
      - type: spring             # spring | tap | well | stream | other
        photo: IMG_1234          # месца на трэку — па часе здымкі гэтага фота
        water: true              # ці была вада: true | false
        seasonal: true           # перасыхае ў сухі сезон
        treat: false             # ці трэба апрацоўваць ваду
        note: "Труба каля сцежкі, добры напор."
  getting_there:
    - type: taxi                 # car | taxi | marshrutka | bus | train | other
      from: "Батумі, парк Качынскіх"   # па змаўчанні — home з config.yaml
      to: "Мілісі"
      time: "1:10"               # у дарозе: г:хх або хвіліны
      km: 42
      price: 80                  # лары
      price_for: car             # car | person
      trip: one_way              # one_way | round_trip
      date: 2025-05-17           # на якую дату цана
      boarding: "Месца пасадкі"
      road: "Апошнія 5 км — грунтоўка."
  parking: "Дзе пакінуць машыну."
  places:
    - type: shelter              # firepit | shelter | swing | camp | signpost | viewpoint | table | toilet | parking | obstacle | other
      name: "Альтанка каля вадаспада"
      photo: IMG_1240
      note: "Стол і лаўкі."
  surface: "Грунт, камяні."      # пакрыццё сцежкі
  marking: "Маркіроўкі няма."    # маркіроўка і навігацыя
  obstacles: "Брод праз 3 км."
  signal: "Сувязь знікае пасля 5 км."
  dangers: "Пастуховыя сабакі."
  gear: "Палкі, гетры."
  season: "Травень–кастрычнік."
  overnight: "Роўныя пляцоўкі каля возера, вада побач."
  after: "Дзе паесці, крама, начлег, агульны кошт."
  suitable: "Дзецям ад 10 гадоў; з сабакам можна."
```

Месца крыніцы вады або асаблівага месца можна пазначыць чатырма спосабамі (дастаткова аднаго):

* `photo: IMG_1234` — фота з падтэчкі «Сайт»; месца знаходзіцца па часе арыгінальнага здымка з EXIF, фота
  адкрываецца побач. Калі такога часу ў фота няма (напрыклад, пасля рэдактара застаецца толькі дата змены),
  месца не выдумляецца — пазначце яго іншым спосабам. Калі ў тэчцы ёсць `A.jpg` і `A.png`, пішыце поўнае імя;
* `time: "10:58"` — калі вы там былі (для шматдзённага паходу дадайце `day: 2`). Час павінен трапляць у
  запіс трэку: момант у доўгім перапынку паміж турамі або па-за запісам застаецца без месца;
* `km: 7.1` — кіламетр ад пачатку дня па профілі вышыні;
* `at: [41.53, 41.82]` — каардынаты [шырата, даўгата]; для месца збоку ад трэку паказваецца адхіленне.

`hike new` дадае гэты шаблон у канец чарнавіка закаментаваным. Памылка ў полі (не той тып значэння, дзень,
час або кіламетр па-за трэкам) дае папярэджанне пры зборцы і не спыняе яе: поле прапускаецца, а запіс
застаецца без месца. Расход вады спісам па днях лічыцца поўным, толькі калі лічба ёсць за кожны дзень.

## Як гэта працуе

```
config.yaml           шляхі і налады (тэчка з фота, канал YouTube, віды спорту Komoot)
content/hikes/*.yaml  апісанні паходаў, якія пішаш ты
scripts/              Python-скрыпты (hike komoot | youtube | new | build | serve)
cache/                (не ў git) туры Komoot, спіс відэа, кэш рэгіёнаў і фота
docs/                 гатовы сайт для GitHub Pages
  index.html, assets/ карта (MapLibre), панэль, профіль вышыні, галерэя (PhotoSwipe)
  data/               hikes.json і трэкі (`tracks/<slug>-<хэш>.json`), якія генеруе `hike build`
  photos/             фота ў WebP (2000 px + мініяцюры 640 px)
```

* Пароль Komoot выкарыстоўваецца толькі падчас `hike komoot` і нікуды не захоўваецца.
* Спасылка «Трэк у Komoot» з'яўляецца толькі для публічных тураў. Прыватныя туры
  для наведвальнікаў усё роўна не адкрыюцца.
* Фота пераціскаюцца толькі тады, калі змяніліся (`hike build --force`, каб пераціснуць усе).
  Метаданыя EXIF, у тым ліку GPS, з фота на сайце выдаляюцца.
* `hike build` не губляе апублікаванае, калі крыніцы недаступныя:
  * тэчка з фота недаступная (дыск `F:` не падключаны) або тэчку паходу перайменавалі — застаюцца
    апублікаваныя раней фота з тым жа парадкам, вокладкай і пунктам на карце;
  * у `cache/komoot` няма тура (напрыклад, праект толькі што скланаваны) або тур у кэшы без каардынат —
    застаецца апублікаваны трэк;
  * фота не чытаецца — застаецца яго папярэдняя версія, а новае пашкоджанае фота прапускаецца;
  * няма мініяцюры апублікаванага фота — замест яе паказваецца само фота; няма поўнай копіі, а крыніца
    недаступная — паказваецца мініяцюра.

  `hike komoot` таксама не замяняе добры трэк у кэшы няпоўным адказам Komoot (без каардынат): такі тур
  лічыцца неабноўленым, і наступны запуск спрабуе зноў.

  Новая версія фота або трэку атрымлівае новае імя з хэшам (`img-2-1a2b3c4d.webp`) і не перазапісвае
  файл, на які спасылаецца апублікаваны індэкс. Старыя файлы выдаляюцца толькі пасля запісу новага
  `hikes.json`, таму зборка, якая ўпала на паўдарозе, не ламае сайт.
  Каб прыбраць фота паходу з сайта, выдалі падтэчку «Сайт» або поле `photos_folder`.
* Калі няма самой тэчкі `content/hikes` (напрыклад, яе перайменавалі), `hike build` спыняецца з памылкай
  і нічога не змяняе. Пустая тэчка — гэта наўмысна пусты сайт.
* «Спампаваць GPX» збірае файл у браўзеры з таго ж трэку, што паказаны на карце (спрошчаны да 3 м, без
  часу): увесь паход або выбраны дзень. Асобных GPX-файлаў у `docs/` няма.
* У падвале панэлі паказваецца версія сайта з файла `VERSION`: яе запісвае ў `hikes.json` каманда
  `hike build`, таму пасля змены версіі сайт трэба сабраць зноў (тэст правярае, што яны супадаюць).
* Падкладкі карты: OpenTopoMap, Esri World Imagery, CARTO; рэльеф: AWS Terrain Tiles.

## Публікацыя на GitHub Pages (адзін раз)

1. Ствары пусты рэпазітар на GitHub, напрыклад `my-hiking`.
2. У `D:\IT\my-hiking`:

   ```powershell
   git init -b main
   git add -A
   git commit -m "Першая версія"
   git remote add origin https://github.com/<login>/my-hiking.git
   git push -u origin main
   ```

3. На GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**,
   галіна `main`, тэчка `/docs`.
4. Праз хвіліну сайт будзе на `https://<login>.github.io/my-hiking/`.

## Тэсты

```powershell
.\.venv\Scripts\python -B -m unittest discover -s tests -q
```

Тэсты працуюць у часовых тэчках: сетка, тэчка з фота і `cache/` не патрэбныя.
Тэсты інтэрфейсу (`tests/js`, Node.js + jsdom) запускаюцца з таго ж `unittest`;
без Node.js або без `npm install` яны прапускаюцца. Асобна: `npm test`.

## Першае ўсталяванне на іншым камп'ютары

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
npm install   # толькі для тэстаў інтэрфейсу
```
