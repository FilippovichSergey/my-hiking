# Мае паходы

Сайт-карта маіх хайкінгаў: трэкі з Komoot, фота, відэа з YouTube і ўражанні.
Беларуская, руская і англійская мовы, светлая і цёмная тэма, 3D-рэльеф, фільтры і агульная статыстыка.
На старонцы паходу можна спампаваць трэк у GPX і скапіяваць спасылку на паход.

## Як дадаць новы паход

1. Запішы тур у Komoot (від спорту «Пешы паход» або «Альпінізм»).
   Шматдзённы паход = асобны тур на кожны дзень.
2. Скапіюй 10–20 лепшых фота ў падтэчку `Сайт` у тэчцы паходу:
   `F:\Фота і відэа\20250517_Зялёнае_возера\Сайт\`.
   Падыходзіць і назва `для сайту`.
3. У тэрмінале ў `D:\IT\my-hiking`:

   ```powershell
   .\hike komoot    # спампаваць туры (спытае email і пароль Komoot)
   .\hike youtube   # абнавіць спіс відэа, калі выйшла новае
   .\hike new       # стварыць чарнавік content\hikes\<дата-назва>.yaml
   ```

4. Адкрый новы `.yaml` і дапішы: рускую і англійскую назвы, складанасць, уражанні.
   Правер, ці правільна падабраныя відэа.
5. Збяры і паглядзі сайт:

   ```powershell
   .\hike fetch     # надвор'е, курс лары, падказкі OpenStreetMap, дарога на машыне (інтэрнэт; пароляў не трэба)
   .\hike build     # фота → WebP, трэкі, docs\data\hikes.json
   .\hike serve     # http://localhost:8000
   ```

6. Апублікуй:

   ```powershell
   git add -A
   git commit -m "Паход: Зялёнае возера"
   git push
   ```

## Файл паходу (`content/hikes/*.yaml`)

```yaml
date: 2025-05-17
end: 2025-05-18             # толькі для шматдзённага паходу без трэку
title:
  be: "Зялёнае возера"
  ru: "Зелёное озеро"       # калі пуста, паказваецца беларуская назва
  en: "Green Lake"          # калі пуста, паказваецца беларуская назва
region:
  be: "Аджарыя"
  ru: "Аджария"             # для рэгіёнаў Грузіі можна не пісаць: руская назва бярэцца з табліцы
  en: "Adjara"
difficulty: medium          # easy | medium | hard | expert
photos_folder: "20250517_Зялёнае_возера"
cover: _MG_0945.JPG         # неабавязкова; інакш першае фота па часе здымкі
komoot:                     # туры аднаго дня аб'ядноўваюцца ў адзін дзень
  - 1234567890
youtube:
  - VQ3BMsY4Fjs
location: [41.65, 41.87]    # [шырата, даўгата] толькі для паходу без трэку
hidden: true                # неабавязкова: схаваць паход з сайта
impressions:
  be: |
    Першы абзац.

    Другі абзац (абзацы раздзяляюцца пустым радком).
  ru: |
    Первый абзац.
  en: |
    First paragraph.
```

**Мовы.** Сайт паказваецца па-беларуску, па-руску і па-англійску (кнопкі BY · RU · EN, адрасы `#/be/…`, `#/ru/…`,
`#/en/…`). Любы тэкст у файле паходу можна пісаць на трох мовах: `be`, `ru`, `en`. Абавязковай мовы няма:
калі тэксту на мове наведвальніка няма, паказваецца блізкая — для рускай беларуская, для беларускай руская,
і толькі потым англійская; для англійскай — беларуская. Таму ўражанні, напісаныя толькі па-беларуску, рускі
чытач убачыць па-беларуску. Пошук знаходзіць паход па назве на любой мове.

Даты паходу з трэкам: пачатак — `date`, але не пазней за першы дзень трэку (назва тэчкі магла «з'ехаць» на
дзень), канец — апошні дзень трэку. Без трэку канец задае `end`; няправільны `end` (напрыклад, 31 лютага
ў двукоссі) адкідаецца з папярэджаннем.

`hike build` спыняецца з паведамленнем і не змяняе індэкс сайта, калі ў файле паходу памылка YAML (у тым
ліку неісная дата без двукосся) або ў паходу няма ні сапраўднай `date`, ні трэку з датай.
Тур, паўтораны ў `komoot:`, улічваецца адзін раз.

Калі тур або тэчку не трэба ператвараць у паход, дадай іх у `content/ignore.yaml`.
Туры, даты якіх трапляюць у выключаную тэчку, таксама прапускаюцца.
`hike new` ніколі не перазапісвае існуючыя файлы: пры супадзенні імя дадаецца `-2`, `-3`…

## Фота на карце

Калі паход адкрыты, на карце стаяць значкі з камерай там, дзе зроблены фота. Націск на значок паказвае
акенца з фота, націск на фота — галерэю. Значкі, якія на экране накладаюцца, зліваюцца ў адзін з лічбай
(у акенцы тады ёсць стрэлкі); пры набліжэнні карты яны разыходзяцца.

Месца здымкі вызначаецца пры `hike build`, пісаць нічога не трэба:

* калі ў фота ёсць GPS і ён не далей за 300 м ад трэку — гэта сам пункт GPS (звычайна фота з тэлефона);
  калі трэк праходзіць там некалькі разоў («туды і назад», месца каля развароту), кіламетр бярэцца ад праходкі,
  бліжэйшай па часе да здымкі. Новая праходка лічыцца з месца, дзе трэк вярнуўся назад. Праходка, якая, пакуль
  трэк не адышоў ад пункта GPS далей за 300 м, больш як на 30 м далейшая за найбліжэйшую, не лічыцца: суседні
  віток серпанціну — не месца здымкі;
* інакш — месца на трэку ў момант здымкі, паводле часу арыгінальнага здымка з EXIF (фота з камеры), і толькі
  калі здымак зроблены падчас запісу трэку.

Фота застаецца без значка, калі месца невядомае: няма ні часу здымкі, ні GPS (напрыклад, пасля рэдактара);
яно зроблена да старту або пасля фінішу запісу трэку; у камеры стаяла няправільная дата. Месца не выдумляецца.
Таму перад паходам варта праверыць дату і час у камеры — гл. [CHECKLIST.md](CHECKLIST.md).

**Калі ў камеры ўжо стаялі не тая дата або час**, напішыце ў файле паходу папраўку — фота вернуцца на карту
і стануць у галерэі па сапраўдным часе здымкі (самі фота і іх EXIF не мяняюцца):

```yaml
photo_clock:
  - date: 2025-11-25         # фота з такой датай у камеры…
    real_date: 2025-10-25    # …на самай справе зробленыя ў гэты дзень (час сутак — як у камеры)
  - files: "DJI_*"           # або: фота з такімі імёнамі (* — любыя знакі, ? — адзін; можна спісам)…
    shift: "+1h"             # …перавесці гадзіннік: d — дні, h — гадзіны, m — хвіліны, напрыклад "-1d 2h 30m"
```

У запісе можна спалучаць `date` і `files` (тады патрэбна і тое, і другое) і `real_date` з `shift`. Для фота
дзейнічае першы запіс, які яму падыходзіць. Шаблоны імёнаў пішыце ў двукоссі. Тая ж папраўка дзейнічае
і для месцаў, пазначаных праз `photo:` у практычнай частцы.

## Практычная частка

На старонцы паходу ёсць блок «Практычная інфармацыя». Пад кожнай яго часткай падпісана, адкуль даныя.

**«Паводле мадэлі Open-Meteo»** — надвор'е падчас паходу, якое спампоўвае `hike fetch`: на старце, у найвышэйшым
пункце і на фінішы — на тую гадзіну, калі вы там былі (тэмпература і «адчуваецца як», вецер і парывы,
воблачнасць, ападкі, снег), а таксама межы за ўвесь час паходу. Гэта архіўны разлік мадэлі па сетцы, а не
замер на сцежцы, таму ў гарах ён прыблізны. Калі сэрвіс прапусціў хоць адну гадзіну паходу, сума ападкаў не
паказваецца (а не «без ападкаў»), і `hike fetch` спытае гэты дзень зноў. Свае назіранні пішыце ў `weather_notes` — яны паказваюцца побач
з подпісам «Мае назіранні». Калі трэк змяніўся, запусціце `hike fetch` зноў.

**«З OpenStreetMap, мной не праверана»** — падказкі, якія спампоўвае `hike fetch`: крыніцы вады (да 250 м ад
трэку) і месцы (да 150 м) — навесы, месцы для вогнішча і начоўкі, сталы, аглядныя пляцоўкі, паказальнікі,
туалеты. На карце і на профілі вышыні яны паказаныя бляднейшымі значкамі з пункцірам, на старонцы — асобным
спісам са спасылкамі на OpenStreetMap; не больш за 40 на паход. Падказка знікае, калі вы самі пазначылі гэтае
месца ў `practical:` (крыніца вады побач або на тым жа кіламетры, месца таго ж тыпу побач). Прыватныя аб'екты,
прыпынкі транспарту і непітная вада не паказваюцца. У фільтр «Ёсць вада на маршруце» падказкі не ідуць.

**«Разлік сэрвісу маршрутаў»** — дарога на машыне ад `home` з `config.yaml` да старту (і ад фінішу дадому,
калі ён далей за 2 км ад старту — яна лічыцца асобна, у сваім напрамку): адлегласць і час паводле OSRM па
дарогах OpenStreetMap, без уліку затораў і стану дарогі. Калі аўтадарога сканчаецца далей за 300 м ад пункта, гэта падпісана. Тое, як вы дабіраліся на самай
справе, пішыце ў `getting_there` — яно паказваецца побач з подпісам «Мае назіранні».

**«Разлік па трэку»** — лічыцца сам пры `hike build`, нічога пісаць не трэба:

* тып маршруту: колавы, туды і назад, з пункта А ў пункт Б, змешаны (для шматдзённага — і для кожнага дня).
  Тур або дзень, які пачынаецца далей за 1 км ад канца папярэдняга (пераезд), — асобная вылазка: калі тыпы
  вылазак розныя, маршрут «змешаны»;
* старт і фініш: час, вышыня, спасылка «Маршрут да старту»; назва бліжэйшага населенага пункта — з
  OpenStreetMap (`hike fetch`; калі беларускай назвы там няма, паказваецца англійская; руская — толькі
  калі яна ёсць у OpenStreetMap);
* светлавы дзень (узыход і заход без уліку рэльефу) і запас святла пасля фінішу;
* тэмп: хуткасць у руху і час на прыпынкі; рэльеф: набор на кіламетр, найкруцейшыя 500 м пад'ёму і спуску
  (у межах аднаго тура: пераезд паміж турамі дня ўхілам не лічыцца).

Тып маршруту паказваецца на картцы ў спісе, па ім можна фільтраваць.

Крыніцы вады і асаблівыя месцы з `practical:`, у якіх пазначана месца, паказваюцца значкамі на карце і кружкамі
на профілі вышыні (вада — сінім, месцы — карычневым); назва відаць пры навядзенні. Калі хоць у аднаго паходу
запоўненыя такія звесткі, у спісе з'яўляецца фільтр «Ёсць вада на маршруце» / «Можна без машыны» (маршрутка,
аўтобус або цягнік у `getting_there`).

**«Мае назіранні»** — блок `practical:` у файле паходу. Усе палі неабавязковыя; пустое поле азначае «няма
звестак», а не «няма» ці нуль. Тэкст можна пісаць радком або на некалькіх мовах:
`{be: "...", ru: "...", en: "..."}`.

```yaml
practical:
  checked: 2025-05-17            # калі звесткі правераны (па змаўчанні — дата паходу)
  route_type:                    # толькі каб выправіць разлік: loop | out_and_back | point_to_point | mixed
  weather_notes: "Раніцай туман, на хрыбце моцны вецер."
  water:
    drunk: 2.5                   # выпіта, л (для шматдзённага — спіс па днях: [2.5, 3])
    taken: 3                     # неабавязкова: узята на старце, папоўнена, засталося
    refilled: 1
    left: 1.5
    available: true              # ці ёсць вада на маршруце: true | false
    sources:
      - type: spring             # spring | tap | well | stream | other
        photo: IMG_1234          # месца на трэку — па часе здымкі гэтага фота
        water: true              # ці была вада: true | false
        seasonal: true           # перасыхае ў сухі сезон
        treat: false             # ці трэба апрацоўваць ваду
        note: "Труба каля сцежкі, добры напор."
  getting_there:
    - type: taxi                 # car | taxi | marshrutka | bus | train | other
      from: "Батумі, парк Качынскіх"   # па змаўчанні — home з config.yaml
      to: "Мілісі"
      time: "1:10"               # у дарозе: г:хх (хвіліны 00–59) або проста хвіліны лікам
      km: 42
      price: 80                  # лары; даляры лічацца самі па курсе Нацбанка Грузіі (`hike fetch`)
      price_for: car             # car | person
      trip: one_way              # one_way | round_trip
      date: 2025-05-17           # на якую дату цана і курс (па змаўчанні — дзень паходу)
      boarding: "Месца пасадкі"
      road: "Апошнія 5 км — грунтоўка."
  parking: "Дзе пакінуць машыну."
  places:
    - type: shelter              # firepit | shelter | swing | camp | signpost | viewpoint | table | toilet | parking | obstacle | other
      name: "Альтанка каля вадаспада"
      photo: IMG_1240
      note: "Стол і лаўкі."
  surface: "Грунт, камяні."      # пакрыццё сцежкі
  marking: "Маркіроўкі няма."    # маркіроўка і навігацыя
  obstacles: "Брод праз 3 км."
  signal: "Сувязь знікае пасля 5 км."
  dangers: "Пастуховыя сабакі."
  gear: "Палкі, гетры."
  season: "Травень–кастрычнік."
  overnight: "Роўныя пляцоўкі каля возера, вада побач."
  after: "Дзе паесці, крама, начлег, агульны кошт."
  suitable: "Дзецям ад 10 гадоў; з сабакам можна."
```

Месца крыніцы вады або асаблівага месца можна пазначыць чатырма спосабамі (дастаткова аднаго):

* `photo: IMG_1234` — фота з падтэчкі «Сайт»; месца знаходзіцца па часе арыгінальнага здымка з EXIF, фота
  адкрываецца побач. Калі такога часу ў фота няма (напрыклад, пасля рэдактара застаецца толькі дата змены),
  месца не выдумляецца — пазначце яго іншым спосабам. Калі ў тэчцы ёсць `A.jpg` і `A.png`, пішыце поўнае імя;
* `time: "10:58"` — калі вы там былі (для шматдзённага паходу дадайце `day: 2`). Месца бярэцца на гэты
  момант — паміж суседнімі запісанымі пунктамі трэку, калі дакладна ў гэты час пункта няма. Час павінен трапляць у
  запіс трэку: момант у доўгім перапынку паміж турамі або па-за запісам застаецца без месца;
* `km: 7.1` — кіламетр ад пачатку дня па профілі вышыні (месца, вышыня і час бяруцца для гэтага кіламетра,
  нават калі запісаны пункт трэку далёка ад яго);
* `at: [41.53, 41.82]` — каардынаты [шырата, даўгата]; для месца збоку ад трэку паказваецца адхіленне
  (да лініі трэку, а не да яго бліжэйшага запісанага пункта). Квадратныя дужкі абавязковыя: запіс без іх
  або не з двух лікаў прапускаецца з папярэджаннем (тое ж для `location` і `home.point`).

Калі трэк з паходу прыбраны, запісы застаюцца, але без месца: яно мае сэнс толькі на трэку.

`hike new` дадае гэты шаблон у канец чарнавіка закаментаваным. Памылка ў полі (не той тып значэння, дзень,
час або кіламетр па-за трэкам) дае папярэджанне пры зборцы і не спыняе яе: поле прапускаецца, а запіс
застаецца без месца. Расход вады спісам па днях лічыцца поўным, толькі калі лічба ёсць за кожны дзень.

## Як гэта працуе

```
config.yaml           шляхі і налады (тэчка з фота, канал YouTube, віды спорту Komoot)
content/hikes/*.yaml  апісанні паходаў, якія пішаш ты
scripts/              Python-скрыпты (hike komoot | youtube | new | fetch | build | serve)
cache/                (не ў git) туры Komoot, спіс відэа, кэш рэгіёнаў і фота, надвор'е, курсы, падказкі OSM, маршруты
docs/                 гатовы сайт для GitHub Pages
  index.html, assets/ карта (MapLibre), панэль, профіль вышыні, галерэя (PhotoSwipe)
  data/               hikes.json і трэкі (`tracks/<slug>-<хэш>.json`), якія генеруе `hike build`
  photos/             фота ў WebP (2000 px + мініяцюры 640 px)
  be/, ru/, en/       старонкі <мова>/<паход>/ для спасылак (іх стварае `hike build`)
  og/                 карцінкі для прэв'ю спасылак (вокладкі паходаў, JPEG 1200×630)
```

* **Спасылкі з прэв'ю.** Адрас паходу на сайце ідзе пасля знака `#`, а яго не бачаць праграмы, якія малююць
  прэв'ю спасылкі: у Telegram усе паходы выглядалі аднолькава. Таму `hike build` стварае для кожнага паходу
  і мовы маленькую старонку `<мова>/<паход>/` з назвай, датай, лічбамі і вокладкай; яна адразу пераводзіць
  на сайт. Кнопка «Падзяліцца» капіюе адрас гэтай старонкі. Патрэбны `site_url` у `config.yaml`; без яго
  такіх старонак няма, і «Падзяліцца» дае звычайную спасылку.
* **Абнаўленне сайта.** GitHub Pages дазваляе браўзеру 10 хвілін трымаць файл у кэшы. Каб пасля публікацыі
  браўзер не змяшаў новыя файлы сайта са старымі, `hike build` запісвае ў `docs/index.html` адзін подпіс
  усіх файлаў `assets/` — у адрасы стыляў і скрыптоў — і подпіс `hikes.json`. Таму **пасля любой змены
  ў `docs/assets/` трэба запусціць `hike build`** (пра гэта нагадае тэст). Радкі паміж каментарыямі
  «hike build: пачатак» і «канец» у `index.html` уручную не правяцца.

* Пароль Komoot выкарыстоўваецца толькі падчас `hike komoot` і нікуды не захоўваецца.
* `hike fetch` звяртаецца да адкрытых сэрвісаў без ключоў: архіў надвор'я Open-Meteo (каардынаты і дата трох
  пунктаў кожнага дня паходу), афіцыйны курс Нацбанка Грузіі (дата цаны), Overpass API (вобласць трэку з запасам
  каля 400 м — падказкі OpenStreetMap), OSRM (каардынаты `home`, старту і фінішу — дарога на машыне) і Nominatim
  (каардынаты старту і фінішу кожнага дня — назва населенага пункта). `hike build` сеткай не карыстаецца: бярэ
  спампаванае з `cache/weather`, `cache/rates.json`, `cache/osm`, `cache/routes.json` і `cache/geocode.json`.
  Без іх сайт збіраецца, проста без гэтых звестак. Спампоўваецца толькі тое, чаго няма; падказкі і дарога
  пытаюцца зноў, калі змяніўся трэк. Публічныя серверы абмяжоўваюць частату запытаў, таму першы запуск для ўсіх
  паходаў займае некалькі хвілін, а падказкі пытаюцца па некалькі паходаў у адным запыце.
* Спасылка «Трэк у Komoot» з'яўляецца толькі для публічных тураў. Прыватныя туры
  для наведвальнікаў усё роўна не адкрыюцца.
* Фота пераціскаюцца толькі тады, калі змяніліся (`hike build --force`, каб пераціснуць усе).
  Метаданыя EXIF, у тым ліку GPS, з саміх файлаў фота на сайце выдаляюцца. Месца здымкі кожнага фота
  (гл. «Фота на карце») публікуецца асобна, у індэксе сайта, і толькі калі яно на маршруце.
* `hike build` не губляе апублікаванае, калі крыніцы недаступныя:
  * тэчка з фота недаступная (дыск `F:` не падключаны) або тэчку паходу перайменавалі — застаюцца
    апублікаваныя раней фота з тым жа парадкам, зададзенай вокладкай і пунктам на карце. Месцы фота на карце
    і месцы запісаў з `photo:`, якія няма з чаго пералічыць, застаюцца, пакуль не змяніліся трэк і `photo_clock`;
    пасля змены яны прыбіраюцца, пакуль дыск зноў не падключаны;
  * у `cache/komoot` няма тура (напрыклад, праект толькі што скланаваны) або тур у кэшы без каардынат —
    застаецца апублікаваны трэк, а з ім ранейшыя разлік па трэку, дарога на машыне і падказкі OpenStreetMap
    (без тых месцаў, якія вы з таго часу пазначылі самі);
  * фота не чытаецца — застаецца яго папярэдняя версія, а новае пашкоджанае фота прапускаецца;
  * няма мініяцюры апублікаванага фота — замест яе паказваецца само фота; няма поўнай копіі, а крыніца
    недаступная — паказваецца мініяцюра.

  `hike komoot` таксама не замяняе добры трэк у кэшы няпоўным адказам Komoot (без каардынат): такі тур
  лічыцца неабноўленым, і наступны запуск спрабуе зноў.

  Новая версія фота або трэку атрымлівае новае імя з хэшам (`img-2-1a2b3c4d.webp`) і не перазапісвае
  файл, на які спасылаецца апублікаваны індэкс. Старыя файлы выдаляюцца толькі пасля запісу новага
  `hikes.json`, таму зборка, якая ўпала на паўдарозе, не ламае сайт.
  Каб прыбраць фота паходу з сайта, выдалі падтэчку «Сайт» або поле `photos_folder`.
* Калі няма самой тэчкі `content/hikes` (напрыклад, яе перайменавалі), `hike build` спыняецца з памылкай
  і нічога не змяняе. Пустая тэчка — гэта наўмысна пусты сайт.
* «Спампаваць GPX» збірае файл у браўзеры з таго ж трэку, што паказаны на карце (спрошчаны да 3 м, без
  часу): увесь паход або выбраны дзень. Асобных GPX-файлаў у `docs/` няма.
* У падвале панэлі паказваецца версія сайта з файла `VERSION`: яе запісвае ў `hikes.json` каманда
  `hike build`, таму пасля змены версіі сайт трэба сабраць зноў (тэст правярае, што яны супадаюць).
* Падкладкі карты: OpenTopoMap, Esri World Imagery, CARTO; рэльеф: AWS Terrain Tiles.

## Публікацыя на GitHub Pages (адзін раз)

1. Ствары пусты рэпазітар на GitHub, напрыклад `my-hiking`.
2. У `D:\IT\my-hiking`:

   ```powershell
   git init -b main
   git add -A
   git commit -m "Першая версія"
   git remote add origin https://github.com/<login>/my-hiking.git
   git push -u origin main
   ```

3. На GitHub: **Settings → Pages → Build and deployment → Deploy from a branch**,
   галіна `main`, тэчка `/docs`.
4. Праз хвіліну сайт будзе на `https://<login>.github.io/my-hiking/`.

## Тэсты

```powershell
.\.venv\Scripts\python -B -m unittest discover -s tests -q
```

Тэсты працуюць у часовых тэчках: сетка, тэчка з фота і `cache/` не патрэбныя.
Тэсты інтэрфейсу (`tests/js`, Node.js + jsdom) запускаюцца з таго ж `unittest`;
без Node.js або без `npm install` яны прапускаюцца. Асобна: `npm test`.

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
npm install   # толькі для тэстаў інтэрфейсу
```
